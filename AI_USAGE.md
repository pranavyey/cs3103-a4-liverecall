**Useful suggestion recorded on 3 November 2026.** Build an immutable history/active snapshot, register the client without an intervening await, and use one sender for both recovery and live updates. This avoids the case where a caption arrives after the history snapshot but before the client joins live delivery. The implementation also shares serialized immutable caption strings across clients. Integration tests exercise concurrent history/live delivery, ordering, late join, and recovery larger than a single permitted frame. These passed locally; public Ubuntu measurements are being collected separately.

**Generated design modified on 3 November 2026.** The first generated connection handler called session(...) before handle_client(...) validated last_segment, last_revision, and history_seconds. A malformed first client hello with session BAD and a negative last_segment was rejected, but had already bound the only session to BAD. Subsequent valid L1 connections could no longer join. Review rejected that ordering. The handler now calls client_resume(...) to validate the complete resume request before session(...) can change state. A regression test first sends the malformed request and then verifies normal L1 delivery succeeds. This is an actual correction made during this project, not a hypothetical example.
